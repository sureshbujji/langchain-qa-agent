# langchain-qa-agent

I built this to answer a question I kept running into as a QA lead evaluating AI features: **how do you regression-test a LangChain agent without an LLM in the loop?**

This repo is a QA-assistant agent built on real `langchain` / `langchain-core` — an LCEL chain plus a tool-calling agent with three tools (calculator, mock bug-tracker search, text summarizer) — backed by a **deterministic fake chat model** I wrote on top of LangChain's own testing fakes. A 10-task golden set asserts tool routing and final answers, so the whole suite runs offline: no API key, no network, green in under a second.

## Architecture

```

                    |  user question    |
                    +--------+----------+
                             |
              +--------------v---------------+
              |  DeterministicFakeChatModel  |  src/fake_model.py
              |  (GenericFakeChatModel       |
              |   subclass: routes by         |
              |   keyword, emits tool_calls)  |
              +--------------+----------------+
                             |
        +--------------------+--------------------+
        |                    |                    |
 +------v------+      +------v------+      +------v-------+
 | calculator  |      | search_bugs |      |summarize_text|  src/tools.py
 | (safe AST   |      | (keyword    |      | (extractive, |
 |  eval)      |      |  search over|      |  stdlib)     |
 +------+------+      | data/bugs   |      +------+-------+
        |             | .json)      |             |
        +-------------+------+------+-----------+
                             |
                    +--------v---------+
                    | ToolMessage      |
                    +--------+---------+
                             |
              +--------------v---------------+
              |  final answer                |
              +--------------+----------------+

  LCEL sidecar:  prompt | model | StrOutputParser   (src/chains.py,
                 bug-triage chain)                  tested in test_chains.py)

  Eval: data/golden_tasks.jsonl (10 tasks) -> src/run_eval.py
        -> reports/eval_report.md
```

The agent itself is `langchain.agents.create_agent` — the stable v1 equivalent of the legacy `create_react_agent` — with a QA system prompt and the three tools bound.

## Quickstart

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt   # langchain==1.4.2, langchain-core==1.6.4, pytest==9.1.1

python -m pytest -q        # 36 tests, fully offline
python -m src.demo         # mock-mode smoke test (also runs in CI)
python -m src.run_eval     # 10-task golden eval -> reports/eval_report.md
```

No `.env`, no keys, no network needed. (`.env.example` documents the optional ones.)

## How the fake model works (the deterministic part)

LangChain ships testing fakes like `GenericFakeChatModel`, but none of them implement `bind_tools` — the agent factory calls it unconditionally. So I subclassed it in `src/fake_model.py`:

1. **`bind_tools` returns `self`.** A fake has no provider schema to inject; it just needs to be a `Runnable` that can emit `AIMessage.tool_calls`.
2. **`_generate` routes on the conversation.** Digits + an operator → `calculator` tool call; `summar*` → `summarize_text`; bug-tracker vocabulary → `search_bugs`. After a `ToolMessage`, it formats the tool result into the final answer. Anything else gets a graceful no-tool reply.

That keeps the tests meaningful: the *agent* decides which tool to call (asserted via `tools_used()`), it isn't reading from a pre-written script. Swapping in a real model later changes nothing else.

## Observability: LangSmith hooks in

Every component here is a LangChain `Runnable` (agent graph, tools, LCEL chain), so tracing needs zero code changes — it's purely env config:

```bash
export LANGCHAIN_TRACING_V2=true
export LANGCHAIN_API_KEY=lsv2-your-key-here   # or LANGSMITH_API_KEY
export LANGCHAIN_PROJECT=langchain-qa-agent
```

With those set, each `ask()` emits a trace with the agent's steps, the tool call (name, args, latency), and the final answer; `triage()` traces the chain's prompt → model → parser stages. Tracing is **off by default** so the test suite stays hermetic — `tests/conftest.py` scrubs these vars, and CI pins `LANGCHAIN_TRACING_V2=false`.

## Using a real model: the one-line change

In `src/agent.py`, `get_model()`:

```python
from langchain_openai import ChatOpenAI; return ChatOpenAI(model="gpt-4o-mini")
```

Replace the `return DeterministicFakeChatModel()` line with the line above (then `pip install langchain-openai` and set `OPENAI_API_KEY`). Everything else — tools, agent wiring, golden eval — works unchanged, and `run_eval` becomes a real regression gate for prompt/model changes.
